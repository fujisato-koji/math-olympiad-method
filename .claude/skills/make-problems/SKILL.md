# 同じ組み合わせの型の問題を作る

この地図では、問題は「組み合わせの型」で似ている・似ていないを決めます（D-020）。型は、その問題を解くのに要る単元の記号の組です（例：`[N-033 合同式, L-005 鳩の巣原理（一般の形）, L-010 背理法]`）。同じ型で、場面と数と言い回しが違う問題が「同様の問題」です。

## 1. 目標の型を決める

- 単元を指定されたら、`roadmap.yaml` でその単元の題、段、前提、日のねらい（plan）を読む。
- 過去問を指定されたら、問題の記録（`problems/` か作業中の記録）の `units`、`gist`、`key` だけを見る。著作権のある問題の問題文は、読んでも写さない。言い回しも借りない。
- 型の単元がすべて、作る問題の段（`stage`）以下にあることを確かめる。

## 2. 型紙で作れるかを見る

計算で答えが決まる単元（段 1〜2 の多く）は、型紙で作る。

```
python tools/generate.py --list
python tools/generate.py --unit N-001 --day 3 --n 6 --seed 11
```

型紙がない単元に何度も問題が要るなら、`tools/generate.py` に型紙を足す（`check` の式を必ず一緒に作る）。

## 3. 考える問題を書く

型紙にならない問題は、次の形で書く。

```yaml
- part: 今日              # 見本、思い出す、今日、挑戦、わけ
  text: 問題の文（段 1〜2 はひらがなの分かち書き）
  figure: 絵（絵文字、改行で行を分ける。なければ書かない）
  choices: [選ぶ問題の選択肢]      # 選ぶ問題だけ
  answer: 答え
  check: 答えを計算する式            # 総当たりでもよい（math、itertools、Fraction が使える）
  hints: [答えを言わない 3 段のヒント]
  paths:                              # 解答のみちすじ。1 本目が基本、2 本目からは別の道
    - [手順, 手順, 答え]
  note: よくある間違い、見るところ（保護者用）
  type: [組み合わせの型の単元の記号]  # この問題の型
  like: IMO-2019-1                    # 型を借りた問題の記号（出どころ。文は写していない）
```

- 場面（人、もの、物語）と数を、元の問題と変える。
- 鍵の一手（`key`）が同じになるようにする。易しくしすぎて型が変わったら、`type` を実際の型に直す。
- ヒントは道筋を途中まで照らすだけにし、最後の一歩は子が踏む（R-14）。
- 単元ごとに、わけを示す問題（`part: わけ`、`explain` に手本）を少なくとも 1 つ入れる（D-016）。

## 4. 答えを確かめる

```
python tools/roadmap.py build
```

- `check` の式が答えと合わないもの、`type` の単元が地図にないもの、わけの問題がない単元は、道具が止める。
- 式 1 つで確かめにくい問題（証明の問題など）は、`check` を書かず、`note` に「確かめ方」を書き、人が読んで確かめる。証明の答案の判定は AI に任せきりにしない（R-16）。

## 5. 公開の決まり

- 自作の問題は公開してよい。著作権の切れた古典は、出典と根拠を書いたうえで問題文ごと公開してよい。
- 著作権のある問題（IMO、JMO、入試など）の問題文と解答は、公開側に置かない。記録するのは出典、自分の言葉の 1 行の骨格（`gist`）、型だけ。
