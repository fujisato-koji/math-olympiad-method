# 図とイラストの多い問題の書き方（D-129〜D-131）

単元の問題を新しく作る係と、作ってある単元を直す係が、どちらも従う決まり。施主の願い「見ただけでわかるように。見本とヒントはできるだけ図とイラストで」を形にしたもの。試しの 6 単元（B-016、H-002、W-043、P-178、E-172、K-122）が手本。

みちすじは、子どもが毎日少しずつ解く学びの地図。1 つの単元は `units/<記号>.yaml` に書く。
施主の願い：**見ただけでわかるように。見本とヒントは、できるだけ図とイラストで。とにかくわかりやすく。**

## 守ること
- 書くのは担当の `units/<記号>.yaml` だけ。ほかのファイルは読むだけ。git の操作（add、commit、checkout、stash）はしない。`python tools/roadmap.py build` や `check` は走らせない（10 分かかり、ほかの係とまざる）。確かめは下の tools/unitqc.py だけを使う。
- 画像をためない：tools/unitqc.py が作る PNG は、Read で見たらすぐ `python tools/unitqc.py --clean <記号>` で消す。自分でブラウザを立てたり、ほかの場所に画像を保存したりしない。
- 問題は自分で作る（本やサイトの問題を写さない）。家でできる観察や実験を場面にする。火や熱い湯、刃物を使う場面には「おうちの ひとと いっしょに」を書く。

## まず読むもの
1. `roadmap.yaml` で担当の単元の行（`- {id: <記号>, ...}`）：題（かっこの中が扱う中身）、段（stage）、水準、日数（days）、前提（needs）。前提の単元の題も読む（その単元で学んだことは使ってよい）。
2. 見本の単元：`units/P-181.yaml`（磁石の極）と `units/H-001.yaml`（物の性質）。頭注・日の並び・選ぶ問題・分かち書きの書き方をまねる。ただし、あなたの単元は**図とイラストをずっと多く**する（見本の単元は図がほとんどない）。
3. 図の見本：`units/G-010.yaml`（円の図の svg）。svg の書き方をまねる。
4. `glossary.yaml`：《用語》の形で書く用語は、ここにあるものだけ。なければ《》を使わず、見本の text か explain で説明する。

## ファイルの形
```yaml
# <記号> <題のかっこの前>
#
# 段 1・水準 1・4 日。<この単元で扱うこと。かっこの中を文に>。
# 子の画面には text、svg、choices、ヒントだけを出す。answer、check、paths、note は保護者用。
# ヒントは答えを書かず、見方・調べ方だけを示す。図の付いたヒントは、答えの手前までを絵で見せる。

id: <記号>
days:
  - day: 1
    items:
      - part: 見本
        text: （子に見せる説明。短い文で 2〜4 行）
        svg: '<svg viewBox="0 0 320 200" xmlns="http://www.w3.org/2000/svg">…</svg>'
        explain: （保護者向けの説明。なぜそうなるか）
      - part: 今日
        text: （問い）
        svg: '<svg …>…</svg>'
        choices: [ア, イ, ウ]
        answer: イ
        check: "'イ'"
        hints:
          - （1 段目：見るところ。文だけでもよい）
          - text: （2 段目：手がかり）
            svg: '<svg …>…</svg>'
          - （3 段目：もう一歩。答えそのものは書かない）
        paths:
          - [1 本目の考えの段, 段, 答えに着く段]
          - [2 本目（別の見方）, 段]
    extra:
      - （予備の問題 2 つ。今日と同じ形）
ri:
  - part: 離
    kinds: [読み取り]
    （腕だめしを 2 問。今日と同じ形）
```
- 日の並び（日数 n で決まる）：n=4 は「導入・練習・わけ・確認」、n=5 は「導入・練習・わけ・混ぜる・確認」、n=6 は「導入・練習・練習・わけ・混ぜる・確認」。かっこの中の中身を日に割り振り、前の日に後ろの日の中身を先取りしない。
- 各日の問題：見本 1（導入・練習の日。その日の新しいことを絵で見せる）、今日 4〜6、挑戦 1、2 日目からは前の日をふり返る思い出す 1〜2。わけの日は part: わけ を 1 問（explain とヒント 3 段と paths 2 本）。混ぜる日・確認の日は、それまでの中身を混ぜた今日 5〜6。どの日にも extra（予備）2。
- 問題の決まり（tools/unitqc.py が確かめる）：part は 見本・思い出す・今日・挑戦・わけ・離。見本とわけには explain が要る。ほかの問題には answer とヒント 3 段が要る。答えは、段 1〜2 では 3 けたまでの数か、choices から選ぶもの。選ぶ問題の check は答えをそのまま書いた `"'イ'"` の形でよい。数の問題の check は、問題の数から計算する 1 行の Python 式（使える名前は math、itertools、Fraction と min max len sorted sum range abs all any set divmod pow）。ヒントに答えをそのまま書かない（「イです」「答えは 3」は誤り）。挑戦とわけの paths は 2 本。
- 答えが 1 つに決まる問いにする。選択肢はまぎれのないものにし、正しいものが 2 つにならないようにする。

## 子に見せる文（text、choices、ヒント、svg の中の文字）
- YAML の書き方：行頭が `? `、`|`、`>`、`-`、`*`、`&`、`!`、`%`、`@`、`` ` `` の文字列や、`: `、` #` を含む文字列は、必ず " か ' でかこむ（`- ? は 2 です。` は組として読まれて文が壊れる）。
- 段 1〜2 はかな中心。漢字は、段 1 は小 1 の字だけ、段 2 は小 2 までの字だけ（`tools/kanji-grades.json` の "1"、"2"）。理科のことばも、段の字にないものはかなで書く（ね、くき、は、こおり、すいじょうき、かげ）。段 3 は小 3 まで、段 4 は小 4 まで。
- 段 1〜2 は、P-181 のように文節ごとに半角の空白で区切る（「みずを ひやすと こおりに なります。」）。段 3 以上は区切らない。数・記号・英字の前後には半角の空白。
- svg の中の文字も、子が読むので同じ決まりを守る（tools/unitqc.py は svg の <text> の字も数える）。

## 図とイラスト（いちばん大事）
- **見本には必ず svg のイラストか図を付ける。** その日の新しいことを、1 枚の絵で見てわかるように。
- **今日・挑戦の問題も、できるだけ絵を見て答える形にする**（絵の中の様子を見て選ぶ、数を数える、どちらが…かを比べる）。問いの文は短くして、絵が中身を語るようにする。
- **ヒントは 3 段のうち少なくとも 1 段（できれば 2 段）を、図の付いたヒント（text と svg）にする。** 答えの手前までを絵で見せる（見るところに色の丸や矢印、比べる 2 つを並べる、変わる前と後を並べる）。答えそのもの（正解の選択肢）は描かない。
- 描き方：
  - 単純な形を組み合わせる（circle、ellipse、rect の rx、path、line、polygon）。写実より「見てわかる」を優先する。1 枚に描くものは 1〜3 つ。大事なところだけ色を付け、ほかは線だけにする。
  - 例：植物＝茎の線、葉は楕円を少し傾ける、花は小さな円を 5 つ、根は細い線を枝分かれ。太陽＝円と短い線を放射状に。月＝円に影の円を重ねる（形の移り変わりは横に並べる）。氷＝角の丸い四角に水色、水＝波の線と水色、湯気＝くねった線。人＝丸い頭と体の線（顔は点 2 つと弧）。影＝灰色の形を光と反対側に。矢印は線と小さな三角（marker を使わず polygon で描く）。
  - 線は `stroke="currentColor"`（暗い画面でも見える）、太さ 2。ぬりは淡い色に `fill-opacity` .35〜.7。色見本：黄 #f3c969、空色 #7fc8f8、緑 #7bc96f、赤 #f08080、茶 #c9a36b、紫 #b39ddb、灰 #c8ccd6。文字の色は `fill="currentColor"`。
  - `viewBox="0 0 320 200"` を基本に（横長）。width と height は書かない。文字は font-size 13〜16、text-anchor で寄せ、図とかさならないように置く。
  - 使えないもの：script、foreignObject、on…= の属性、href、url(…)、外の画像。<defs> の marker も使わない（矢印は polygon）。
  - 天びんも svg で描く（上皿てんびん：台・柱・横の棒・皿 2 つ、傾きは棒の角度）。前の balance:（D-042）は、答えを見ない係の道具にも確かめの PNG にも出ないので使わない。unitqc.py が誤りとして出す。check が bal を使っていたら、式も数で書き直す（D-132 の追記）。
- 描いたら必ず tools/unitqc.py で PNG にして Read で見る。はみ出し、かさなり、小さすぎる文字、何の絵かわからないものを直す。見たら --clean で消す。

## 試しの 6 単元の審査で多かった指摘（書く前と書いたあとに、自分で見る）
- **ヒントが答えをほぼ言っている**（いちばん多い）。「さわると つめたくて すきとおって いるのは どれ」のように、正解だけに当てはまる言い方は答えと同じ。3 段目でも、見るところ・調べ方・一歩手前までにする。ヒントの図に正解の選択肢そのもの（正解の絵、正解の場所の印）を描かない。
- **問いと絵が合わない**：「あわが 出る なべは」と聞くのに、絵のなべにあわも火の強さの違いもない、など。問いに答えるための手がかりが、絵か文のどちらかに必ずあるようにする。ただし、手がかりを描きすぎて絵を見ただけで答えが出る形にもしない（その場合は問いの文を変える）。
- **図が小さい・何の絵かわからない**：茶色の四角だけの「木」、小さいマスの上の小さなロボット。大事なものは viewBox の半分ほどの大きさに。物は特徴（丸太の年輪、葉のすじ、へたの星）を 1 つ描き足す。
- **数が問いの文に書いてあって、絵を数えなくても答えが出る**。数える問題は文に数を書かない。
- **子の見る文で説明していない用語**（explain にしか書いていない「ふたば」など）を、問いやヒントで使わない。見本の text で先に言う。
- **同じ単元の中で図の描き方がそろっていない**（同じ紙の波がギザギザだったりなめらかだったり）。1 つの物は単元の中で 1 つの描き方に。
- 理科の事実：「この あと ひらく はっぱ」のように、時がたつと答えが変わる言い方をしない（「さいしょに ひらく」）。

## 確かめ（書いたら必ず。誤り 0、漢字 0 になるまで）
作業ツリーの根で `PYTHONIOENCODING=utf-8 python tools/unitqc.py <記号>`
- 「誤り」は check の決まりの誤り（0 にする）。「段 n の学年より上の漢字」も 0 にする（かなに開く）。図の中の文字（svg の <text>）も数える。kinds の一覧（[読み取り] など）は数えないので、頭注に字を足して通す必要はない。頭注に書いた漢字は「使ってよい字」に入ってしまうので、頭注に子の文で使わない漢字をむやみに書かない。
- 図を PNG にまとめる（腕だめしの図も入る。18 図ごとに shot-<記号>-1.png、-2.png … に分かれる）。Read で見て直し、最後に `--clean`（分かれた PNG も全部消える）。
- 自分で全部の問題を解き、答えが 1 つに決まること、ヒントが答えを書いていないことを確かめる。
- ファイルは UTF-8、改行は LF でよい。YAML の文字列に : や # や ' が入るときはかこみ方に気をつける（svg は 1 行の ' でかこみ、中では " を使う）。

## 戻すもの（要約だけ、10 行以内）
日ごとの問題の数（見本・今日・挑戦・思い出す・わけ・予備）、svg の数（問題の図とヒントの図）、qc の結果（誤り・漢字）、自分で気になった点。


## 答えを見ない解き直し（D-131）
書く係・審査の係・直す係が答えを知ったうえで読むと、図と答えの食い違い（左右を反対にした図で ア・イ を入れかえ忘れる、など）を見逃す。そこで、書き上げた単元は、答え・ヒント・筋道を抜いた問題を、答えを知らない係に解き直させ、ファイルの答えと照らす。
- `python tools/blind.py build <記号>`：答えを抜いた問題を、リポジトリの外（OS の一時フォルダの michisuji-blind）に書く。
- `python tools/blind.py render <記号> <係の名>`：文と選択肢と図を画像にする（見たら `clean <記号> <係の名>` で消す）。
- `python tools/blind.py key <記号>`：照らす側だけが使う答えの一覧。解く係には使わせない。
- 解く係は units/ と site/ と docs/ を開かない。答えが 2 つありうる問い・図と文が合わない問いにも印を付けて返す。
- 食い違いと印の付いた問いは、図を見て直す（図と問いのどちらかを直し、答えが 1 つに決まるようにする）。

## 作ってある単元を直すとき（D-131）
- 直す前に `python tools/stamp.py <記号>` で、全部の問題に今の記号（中身の指紋）を `id:` として書く。図を足したり文を直したりしても、子の解いた記録が引き継がれる（D-044）。答えや問いの意味を変えたときだけ、その問題の `id:` の行を消す（前の記録は意味がなくなるため）。`id:` は必ず引用符でかこむ（数字だけの指紋は 8 進の数に読まれる）。
- 問題の数・日の並び・part は変えない。消してよいのは、直しても答えが 1 つに決まらない問題だけ（消したら記録に残す）。
- kinds: [最難関] の問題（決勝級）は、中身を変えない。答えのまちがいを見つけたら記録に残す。
- 漢字の警告（段の学年より上の漢字）も、その単元の分はあわせて直す。
