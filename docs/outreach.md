## 4. 戦略の案（推奨）

### 段 0 土台（打ち上げの前に）

1. **ライセンス**：中身（単元・概念・図）は CC BY 4.0、道具と画面のコードは MIT を推奨します。CC BY は出典を書けば誰でも使え、OpenStax の教科書と同じ形です。作り変えたものも開いたままにしたいなら CC BY-SA 4.0（Wikipedia と同じ形）。非営利だけに限る CC BY-NC は、学校や会社の中で使いにくくなり、広まりを弱めます。大会の問題は、いまどおり出典と型だけにします（P-06）。AI が作った文の著作権の扱いは国によって定まっていませんが、ライセンスを付けておけば、使う側は迷わずに済みます。
2. **名前と住所**：国際的に読める名前と、独自のドメインを推奨します。施主の名前が住所から消え（P-08）、置き場所を替えても住所が残ります。リポジトリ名の変更は「中身がそろってから」という前の決まりがあるので、名前を決めるのはここが機会です。
3. **静的なページ**：build が単元・概念・目標ごとに HTML を書き出すようにします（例：/en/unit/M-004/、/en/concept/det-product/、/en/goal/imo/）。各ページに題・説明・og の絵・hreflang（ja と en）・schema.org の LearningResource を付け、sitemap.xml と robots.txt も作ります。いまの画面は、そのまま学ぶための入口として残します。
4. **英語**：はじめに、地図・目標・単元の題と日のねらい・概念の目録を、全部英語にします（量が少なく、地図全体が英語で使えるようになる）。問題は、小中の算数 130 単元と決勝級 52 問から英語にします。訳すときも、答えと図は変えずに文だけを替え、いまの答えを見ない解き直しで確かめます。水準ごとの字の決まりは日本語にしかないので、英語の読みやすさの決まり（文の長さと語の範囲）を別に作ります。
5. **誤りの知らせ口**：問題と概念ごとに「まちがいを知らせる」を置きます（GitHub の issue を記号つきで開く、保護者向け）。単元ごとに確かめの状態（答えを見ない係 2 人で解き直し済み、など）を出します。
6. **測り方**：Google Search Console（使う人を追跡しない）と GitHub の数字にします。クッキーを使わない数え方を足すかは、施主が決めます（P-05）。
7. **軽くする**：data.js を、地図に要る分と単元ごとの分に分け、最初に送る量を 0.5 MB 以下にします（回線の細い地域と帯域の上限のため）。

### 段 1 日本語で小さく出す

日本語の中身はすでにあるので、先に日本語で小さく出し、壊れる所と分かりにくい所を直します。出す場所は、note・Zenn・はてな・X と、算数・数学の保護者や先生の集まりです。

### 段 2 英語で打ち上げる

場ごとに見せる面を変え、1 か所に 1 回ずつ出します。

| 場 | 見せる面 |
|---|---|
| Hacker News（Show HN） | 1 本の地図と開いたデータ、AI で教科書を作り検証する方法 |
| Reddit（r/math、r/learnmath、r/matheducation、r/homeschool） | 概念のページ、無料で広告なし、記録は自分のドライブ |
| r/dataisbeautiful、YouTube の短い動画 | 3D の地図が回る動画 |
| AoPS の掲示板 | 決勝級の問題と、構造の網羅 |
| Product Hunt、X・Bluesky・Mastodon | 夢の仕事への道のりのカード |

用意するもの：英語の入口のページ、30〜60 秒の動画、目標ごとの og の絵。

### 段 3 続く流れを作る

- 検索：概念と単元のページを増やす（目録は単元を作り直すたびに増える、D-240）。
- データ：自作の問題（答え・道筋・確かめの式つき）と概念の目録を、Hugging Face にデータとして出す。
- 一覧：awesome-math などの一覧、OER Commons・MERLOT のような開いた教材の目録に載せる。
- 概念に Wikidata の記号を付け、ほかの知識の網とつなぐ。

### 段 4 人の手で広げる

- 訳：AI の下訳を、その言語を話す人が GitHub の PR で直す。英語の次の言語は、学ぶ人の多さと協力者の有無で決めます（スペイン語、ヒンディー語、中国語、ポルトガル語、アラビア語、フランス語、インドネシア語など）。中国本土では GitHub Pages と Google が使えないので、別の置き場所と記録の方式が要ります。
- 印刷できる束、ほかのサイトに組み込める形。
- 数学サークル、大会の委員会、回線の細い地域の NGO と組む（PWA はつながっていなくても動く）。

- 名前：「michisuji」は、2025-03-24 に作られた別の人の組織で使えない（公開のリポジトリ 0、2026-11-21 に確かめた）。空いている案は michisuji-org、michisuji-project など。住所は https://<組織>.github.io/<リポジトリ>/ になる。
- 施主にお願いすること：github.com で組織を作る（無料の形。API では作れない）。Google Cloud の OAuth クライアントの「承認済みの JavaScript 生成元」と、Picker の API キーの「HTTP リファラー」に新しい住所を足す。
- 取りまとめがすること：
  1. リポジトリを組織へ移す（GitHub の移管。git と Web の住所は自動で新しい住所へ転送される）。
  2. Actions の書き込みの許可と Pages の設定を確かめる（pages.yml が gh-pages へ push できるか）。
  3. 住所の決め打ちを直す：README、docs/google-drive.md、site/privacy.html、site/sync.js。ログインの Worker の ALLOWED_ORIGINS（auth/wrangler.toml）に新しい住所を足して deploy する。
  4. 前の住所 fujisato-koji.github.io/math-olympiad-method/ は、移管で転送されない見込み（GitHub の転送は git と Web の住所。移す前に GitHub の文書で確かめ、出典に足す）。前の住所に、# のあとを引き継いで新しい住所へ送るだけのページを残す。

## 8. アプリのストアに載せるか（施主「google play とかに乗る形にしなくていいか」、2026-11-21）

いまの画面は PWA（ホーム画面に置けて、つながっていなくても動く）です。この PWA をそのまま包んでストアに出す方法があり、中身を直しても、ストアに出し直さずに新しい中身が届きます。

| ストア | 包み方 | 費用 | 公開される名前 | 載せる条件と危うい所 | 推奨 |
|---|---|---|---|---|---|
| Google Play | Trusted Web Activity（Bubblewrap が作る署名済みの APK をそのまま出せる） | 登録は 1 回 US$25 | 個人のアカウントは、開発者名・**法的な氏名**・国・連絡のメールが公開される。組織のアカウントは D-U-N-S 番号が要る | ①サイトとアプリの結び付けのファイルを、住所の根 `/.well-known/assetlinks.json` に置く（GitHub の組織なら <組織>.github.io のリポジトリで置ける）。②2023-11-13 より後に作った個人のアカウントは、12 人以上が 14 日続けて試してからでないと本番に出せない。③子どもを対象に含めると Families の決まりがかかる（端末の識別子を送らない、子ども向けに認められた SDK だけ、プライバシーの説明、子ども向けに認められていない OAuth は使えない） | **載せる。ただし組織へ移したあと、日本語で小さく出したあと** |
| Microsoft Store | PWABuilder で包む（コードの直しは要らない、審査は通常 24〜48 時間） | 個人も会社も登録は無料（新しい登録の流れで） | 未確認 | 使うのは PC が主 | 余力があれば。費用がかからず速い |
| Apple App Store | 包むことはできる | 年 US$99 | 個人は法的な氏名が売り手として出る | 決まり 4.2 が「作り直しただけのウェブサイト」を越える機能を求めるので、包んだだけでは断られるおそれ。ビルドに Mac が要る | 見送る。iPhone では、Safari の「ホーム画面に追加」で同じ画面が使える |

ストアに載せる利点は 3 つです。保護者が「算数 アプリ」とストアで探したときに見つかること、ストアに載っていることが安心の目印になること、ホーム画面に置かれやすいことです。いっぽう、ストアに載せても検索のページや再利用（第 3 節の A・B・D）の代わりにはならないので、段 0 の土台が先です。

Google Play の進め方の案：
1. 組織へ移して住所を決める（TWA は住所に結び付くので、あとで住所を変えるとアプリも出し直しになる）。
2. 公開する名前を決める（下の Q6）。
3. 日本語で小さく出すとき（段 1）に、試す人を 12 人以上集め、14 日続けて試してもらう。
4. 対象の年齢は「保護者と子ども」にし、Google ドライブへの保存（ログイン）は、保護者が開く設定の奥に置く（子どもがログインに触れない形。R-15 にも合う）。端末の識別子を送らない・広告なし・追跡なしは、いまの作りのままで満たす。
5. Bubblewrap で包み、assetlinks.json を置き、ストアの説明とプライバシーの説明（site/privacy.html）とデータの安全性の欄を書く。

### 8.1 (b) 個人事業の D-U-N-S 番号で組織のアカウントにするのに要ること（2026-11-21 に調べた）

施主「b に必要なことを調べて」。法人も個人事業の届出もないところから、屋号で個人事業を始め、東京商工リサーチ（TSR）で D-U-N-S 番号を取り、Google Play の組織のアカウントで出す場合です。

**公開されるもの（いちばん大事）**：組織のアカウントでは、法的な名称・D-U-N-S 番号・**法的な住所**・開発者のメール・開発者の電話が公開されます。住所は国だけとは書かれておらず、全体が出ると読むのが安全です。収益化しなくても出ます（個人のアカウントで住所の全体が出るのは収益化したときだけ）。つまり (b) は、氏名を屋号に替える代わりに、**事業所の住所・電話・メールを公開する**ことになります。自宅を事業所にすれば、自宅の住所が出ます。

## 9. 2026-11-21 夕の決定と、段階 0 の作業計画

施主が別の会話でまとめたメモ（2026-11-21）で、次のように決めた。第 6〜8 節のうち、これと食い違う所はこちらを優先する。
