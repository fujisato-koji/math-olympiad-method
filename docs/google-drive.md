# 記録を Google ドライブに置く（D-049）

画面「みちすじ」の記録（人ごとの進み具合、解いた問題、星、かかった時間、呼び名）を、ログインした人の Google ドライブに置き、PC からもスマホからも同じ記録を開けるようにする。

## しくみ

- **置き場所**：ログインした人の Google ドライブの、このページ専用の隠しフォルダ（appDataFolder）に、ファイルを 1 つ置く（`michisuji-records.json`。前の `michisuji-store.json` は人が混ざったので使わない、D-051）。ドライブのほかのファイルは見えない。
- **こちらは預からない**：記録はこちらに届かない（R-23 のまま）。動かすのは、ログインを保つための何も保存しない小さなサーバだけ（下の「ログインを保つ」）。画面と問題はこれまでどおり GitHub Pages から配る。
- **ログイン**：Google のコードの方式（Google Identity Services）と、ログインを保つサーバ（D-058）。一度つなげば、その端末では切れない。鍵（アクセストークン）はそのタブの中（sessionStorage）だけに置き、約 1 時間で切れたら、黙って取り直す。サーバの住所が空のときは、前のトークンの方式（約 1 時間で切れ、ヘッダーの札を押すとログインし直す）。
- **権限**：`https://www.googleapis.com/auth/drive.appdata` だけ。Google の分類では機密でない範囲で、基本の確認だけで使える（[Google Drive API の権限の選び方](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)）。
- **合わせ方**：開いたとき、ログインしたとき、記録を保存してから 4 秒後（続けて解いている間はまとめて 1 回）、画面を閉じるとき、開いているあいだは 1 分ごと、ほかのアプリやタブから戻ったとき（D-056）に、ドライブの記録を読み、端末の記録と合わせ、合わせたものを両方に置く。中身が変わらなければ書き戻さない。
  - 人は、記号（pid）が同じか、記号が違っても呼び名が同じなら同じ人として合わせる（D-051）。呼び名で合わせたときは記号の小さいほうを残す。消した人の記号は `deleted` に残し、どちらの端末で消しても戻さない。呼び名は後で付けたほうを残す。
  - 記録の窓の「ドライブの記録で置き換える」は、この端末の記録を使わず、ドライブの記録をそのまま読み込む。
  - 単元の日は両方を合わせる（同じ日は新しいほう）。済は早いほうの日付。とばした日も合わせる。確かめは段の進んだほう。
  - 問題ごとの数（解いた回数、一度にできた回数、星など）は大きいほうを残す（同じ記録から伸びたものなので足さない）。
  - 日の記録（あゆみ）は日ごとに大きいほう。ふりかえり待ちは合わせ、済ませたもの（`askDone`）は戻さない。
  - 合わせたあと、記号の付け替えと日の印で、いまの地図に合わせ直す（D-044）。
- **電波がないとき**：端末の中に保存し、ヘッダーの札を「保存待ち」にする。電波が戻ったら、押さなくても合わせる（D-058）。
- **共有の目印**：合わせるたびに読み直す。開いたままの画面でも、ほかの端末で共有を始めたりやめたりしたのが入る（D-058）。
- **ホーム画面のアプリ（PWA）**：`manifest.webmanifest` と `sw.js`。ホーム画面に置くと全画面で開く。つながるときは毎回新しいファイルを取り、取れないときだけ、とっておいたものを出す。
- **プライバシー**：`site/privacy.html`（公開ページの privacy.html）。

道具は `site/sync.js`（ログインとドライブの読み書き）と `site/app.js` の「Google ドライブと合わせる」（合わせ方と画面）。クライアント ID は `site/index.html` の `<meta name="google-client-id">` に書く。空のあいだは、ドライブの欄は出ない。

## 家族と共有する（D-052）

- 隠しフォルダはアカウントごとなので、家族のアカウントとは分け合えない。共有するときだけ、共有する人のドライブに見えるファイル `みちすじの記録.json` を作り、相手に編集の権限を付ける。
- **共有する人**：記録の窓の「家族と共有」に相手のメールアドレスを入れて「共有する」を押す。まず自分のドライブと合わせ、合わせた記録でファイルを作り、相手に編集の権限を付ける。Google から相手にお知らせが届く。
- **共有された人**：お知らせのメールのリンク（`#/join/<ファイル>`）を開き、「記録を開く」を押す。Google の窓にそのファイルだけが並ぶので、選ぶだけでよい（D-054）。選ぶと、その端末の記録と合わさる。リンクがなくても、記録の窓の「共有された記録を開く」から、ファイル選び（Picker）で「みちすじの記録」を選べる。
- **目印**：どのファイルを使うかを、各自の隠しフォルダの `michisuji-link.json` に置く。同じアカウントのほかの端末では、ふつうにログインするだけで共有の記録を使う。
- **共有をやめる**：記録の窓の「共有をやめる」で、自分の隠しフォルダの記録に戻る。共有のファイルそのものは消さない。相手の権限は Google ドライブの共有の設定で外す。
- **権限**：`drive.file`（このアプリで作ったファイルと、自分で選んだファイルだけ）を足した。機密でない範囲。
- 空の「1 人目」（新しい端末で最初にできる人）は、相手に人がいれば合わせるときに足さない。

## ログインを保つ（D-058）

施主の考え：ログインは基本的に切れない、オンラインに戻ったら勝手につなぐぐらいでいい。

- **サーバ**：`auth/worker.js`（Cloudflare Workers、無料の枠で足りる。1 日 10 万回まで）。何も保存せず、記録は通らない。することは 2 つだけ。
  - `POST /auth`：画面が Google から受けた一回きりの番号（code）を、Google でアクセストークンと更新の鍵（リフレッシュトークン）に換える。更新の鍵は暗号にした塊（blob）にして画面へ返す。
  - `POST /token`：画面が持ってきた塊を開き、更新の鍵で新しいアクセストークンを取る。
- **ログイン**：Google のコードの方式（`initCodeClient`、ポップアップ）。Google の部品は、この方式ではログインのたびに同意の画面を出し、更新の鍵を必ず付ける（`access_type=offline`、`prompt=consent`）。そのため、つなぐたびに同意の画面が出るが、つなぐのは端末ごとに一度だけ。
- **塊の置き場所**：端末のブラウザの localStorage（`michisuji.gkeep`）。サーバの住所（workers.dev）と画面（github.io）は別のサイトで、ブラウザによっては cookie を置けないので、cookie は使わない。
- **塊の鍵**：AES-GCM。鍵はクライアント シークレットから HKDF で導く（入れていただく秘密を 1 つにするため）。シークレットを替えると、すべての端末の塊が開けなくなり、各端末で一度つなぎ直す。
- **受ける相手**：公開ページ（`https://fujisato-koji.github.io`）からの呼び出しだけ（`ALLOWED_ORIGINS`）。ブラウザの外からは Origin を偽れるが、塊がなければ何も取れない。
- **つながりが切れるとき**：Google アカウントの設定で許可を取り消したとき、更新の鍵を 6 か月使わなかったとき、同じ人が 100 回を超えてつないだとき（古い鍵から使えなくなる）。サーバが断ると、画面は塊を捨てて札を「つなぐ」にし、押すとつなぎ直す。
- **この端末ではつながない**：塊を捨てるだけで、Google の許可は取り消さない（取り消すと、ほかの端末もつなぎ直しになる）。すべての端末でやめるときは、Google アカウントのサードパーティ アクセスで取り消す。
- **前の方式に戻す**：`site/index.html` の `<meta name="michisuji-auth">` を空にすると、前のトークンの方式（約 1 時間で切れる）に戻る。
- **交換の redirect_uri**：Google の説明では、ポップアップのときは呼んだページの origin。断られたら、前からの書き方 `postmessage` で試し直す。
- 道具：`auth/wrangler.toml`（公開してよい値：クライアント ID、受ける相手）、`auth/test.mjs`（サーバの確かめ。`node auth/test.mjs`、CI でも動かす）。
- **置いた場所**：`https://michisuji-auth.fujisato-koji.workers.dev`（施主の Cloudflare のアカウント、2026-11-09）。直したら `auth/` で `npx wrangler deploy`（シークレットは置き直さなくても残る）。

### 施主にお願いすること（一度だけ）

ご本人のアカウントでしかできない作業です。費用はかかりません。

1. **Cloudflare のアカウント**：[Cloudflare](https://dash.cloudflare.com/sign-up) で無料のアカウントを作る（メールの確認まで）。
2. **サーバを置く**：Claude が `npx wrangler login` を動かすと、ブラウザに Cloudflare の許可の画面が出るので「Allow」を押す。Claude が `npx wrangler deploy` で置き、住所（`https://michisuji-auth.<名前>.workers.dev`）をお知らせする。初めてのときは、workers.dev の名前（`<名前>` の部分）を決める画面が出ることがある。
3. **クライアント シークレットを用意する**：[Google Cloud コンソール](https://console.cloud.google.com/)の「Google Auth Platform」→「クライアント」→「みちすじ」を開く。前からのシークレットの値が見えればそれを、見えなければ「シークレットを追加」を押して出た値をコピーする（あとから見られないことがあるので、4 まで続けて行う）。**Claude には渡さない。**
4. **シークレットを入れる**：[Cloudflare のダッシュボード](https://dash.cloudflare.com/)の「Workers & Pages」→「michisuji-auth」→「設定」→「変数とシークレット」→「追加」。種類は「シークレット」、名前は `GOOGLE_CLIENT_SECRET`、値は 3 でコピーしたもの。「デプロイ」を押す。
5. **アプリを公開**：「Google Auth Platform」→「対象」で「アプリを公開」を押し、「本番環境」にする。テスト中のままだと、更新の鍵が 7 日で切れる（[Google の説明](https://developers.google.com/identity/protocols/oauth2#expiration)）。使う権限は機密でない範囲だけなので、Google の審査は要らない見込み。
6. Claude が `index.html` の `<meta name="michisuji-auth">` にサーバの住所を入れて公開する。各端末で一度「つなぐ」を押す（同意の画面が出る）。以後は切れない。

つなぐときに `redirect_uri_mismatch` で断られたら、「クライアント」→「みちすじ」の「承認済みのリダイレクト URI」に `https://fujisato-koji.github.io` を足す（Google の説明ではポップアップでは要らないが、念のため）。

## Google Cloud の登録（施主が一度だけ行う）

ご本人の Google アカウントでしかできない作業です。費用はかかりません。

1. [Google Cloud コンソール](https://console.cloud.google.com/) に入り、新しいプロジェクトを作る（名前は例えば `michisuji`）。
2. 「API とサービス」→「ライブラリ」で **Google Drive API** を探し、「有効にする」。
3. 「Google Auth Platform」（以前の「OAuth 同意画面」）を開き、「開始」を押す。
   - **ブランディング**：アプリ名「みちすじ」、ユーザー サポートのメール（ご自分）、デベロッパーの連絡先のメール（ご自分）。
     - アプリのホームページ：`https://fujisato-koji.github.io/math-olympiad-method/`
     - プライバシー ポリシー：`https://fujisato-koji.github.io/math-olympiad-method/privacy.html`
     - 承認済みドメイン：`fujisato-koji.github.io`（入れられなければ空のままで進める）
   - **対象**：「外部」。公開の状態は、はじめは「テスト中」のままにし、「テストユーザー」にご自分とご家族の Google アカウントを足す（テスト中は、ここに足した人だけがログインできる）。
   - **データアクセス**：「スコープを追加または削除」で `.../auth/drive.appdata`（Google ドライブのアプリ自身の設定データの表示と管理）を選ぶ。
4. 「クライアント」→「クライアントを作成」。
   - 種類：**ウェブ アプリケーション**、名前：`みちすじ`
   - 承認済みの JavaScript 生成元：`https://fujisato-koji.github.io`（手元で確かめるなら `http://localhost:8765` も）
   - 承認済みのリダイレクト URI：要らない（空のまま）
5. 作られた **クライアント ID**（`…apps.googleusercontent.com` で終わる文字列）を Claude に渡す。`index.html` に入れて公開する。クライアント ID は画面に書く公開の値なので、渡しても問題ない。**クライアント シークレットは渡さない**（ログインを保つときに、ご自分で Cloudflare に入れる。上の「施主にお願いすること」）。
6. **家族と共有するための設定**（D-052）：
   - 「API とサービス」→「ライブラリ」で **Google Picker API** を有効にする。
   - 「API とサービス」→「認証情報」→「認証情報を作成」→「API キー」。作ったキーの「キーを制限」で、アプリケーションの制限を「ウェブサイト」にして `https://fujisato-koji.github.io/*` を足し、API の制限で「Google Picker API」だけを選ぶ。できたキーを Claude に渡す（画面に書く公開の値。使える場所を絞るので渡してよい）。
   - 「Google Auth Platform」→「データアクセス」で、スコープ `.../auth/drive.file`（このアプリで使用する特定の Google ドライブ ファイルのみの表示、編集、作成、削除）を足す。
   - 「対象」のテストユーザーに、共有する相手（奥さまなど）のアカウントを足す（テスト中は、ここに足した人だけがログインできる）。
7. 世界中の人に開くとき：「対象」で「アプリを公開」を押す。使う権限が機密でない範囲だけなので、Google の審査は要らない見込み。ただし、同意の画面にアプリ名やロゴを出すには、ブランドの確認（Google によれば 2〜3 営業日）が要る（[ブランドの確認](https://developers.google.com/identity/verification/authentication-verification)）。

## 確かめ

  - 別の端末では、両方の記録が合わさる。
  - 片方で消した人は、もう片方を開くと消える。
  - 呼び名の変更が届く。
  - ログインが切れると札が「ログイン」になり、押すと合わせ直す。
- クライアント ID と Picker の API キーを index.html に入れた（2026-11-08）。
- 本物の Google で、施主が確かめた（2026-11-08）。
  - PC とスマホで同じ記録が開く。人が混ざった誤りは D-051 で解消した。
  - 奥さまのアカウントとの共有：お知らせのメールの専用のリンクから「記録を開く」を押し、ファイルを選ぶと、同じ記録が開いた（D-052〜D-054）。

- ログインを保つ仕組み（D-058）を、本物の Google とサーバの代わりに返事を作る道具で確かめた（2026-11-09、29 項目、例外 0）。
  - つなぐと、コードの方式で窓が一度開き、塊が端末に置かれ、ドライブに記録が入る。
  - 新しいタブで開くと（鍵がない）、窓を開かずにサーバで取り直して合わせる。
  - ドライブが鍵を断ると、塊から一度取り直して続ける。
  - 電波がないと札が「保存待ち」になり、ドライブには送らない。電波が戻ると、押さなくても合わせる。
  - 開いたまま、ほかの端末が共有の目印を置くと、次に合わせるとき共有のファイルを読む。目印を消すと自分のファイルに戻る。
  - サーバが塊を断ると（許可の取り消し）、塊を捨てて札が「つなぐ」になり、押すとつなぎ直す。
  - 「この端末ではつながない」で塊が消え、Google の許可は取り消さない。
  - サーバの住所が空なら、前のトークンの方式のまま。
  - 前の確かめ（端末をまたぐ記録、家族の共有）も、同じ結果で通った。
- 置いたサーバを外から確かめた（2026-11-09）：公開ページからの下調べに答え、ほかのページは断る。偽の塊は 401。偽の番号には Google が `invalid_grant` と答えた（シークレットが違えば `invalid_client`）ので、シークレットは正しく入った。Google Cloud はブランディング（ホームページとプライバシーのリンク）を入れて「本番環境」にした。
- サーバそのものを `auth/test.mjs` で確かめた（11 項目：塊に更新の鍵が見えない、redirect_uri の試し直し、取り直し、Google が鍵を替えたとき、書き換えた塊・形の違う塊・シークレットを替えたあとの塊は 401、取り消された鍵は 401、変な番号は Google に送らない、ほかのページからは受けない、下調べに答える、シークレットがないと 500）。`wrangler deploy --dry-run` で組み立てが通ることも確かめた。

## これから

- ストアに出すアプリにするときは、ログインの部分をアプリ用のものに差し替える（Google は、アプリに埋め込んだブラウザからのログインを禁じている）。
